gsh — GSH's internal CLI (visible only inside the app's terminals)

`ck` is a shorter name for the same command: `ck list-tabs` == `gsh
list-tabs`. (If you already have your own `ck` alias, yours wins.)

A **tab** is a terminal/agent session (what this CLI addresses). A **pane** is
the split leaf that groups tabs — not addressed here. `list-panes`/`read-pane`
are legacy aliases of `list-tabs`/`read-tab`.

USAGE:
  gsh send      [--tab-id <id>] [--enter] <text>   type text (--enter submits)
  gsh send-key  [--tab-id <id>] <Key>...   press named key(s)
  gsh msg --to <label|tab-id> <text>       message another agent's tab
                                               (typed + Enter, signed with your tab)
  gsh deliver --to <Name/agent> <file> [note]  hand a file to a teammate's
                                               agent on the office network
  gsh peers     [--json]                   agents linked to your tab in the
                                               Agents graph (id, label, harness)
                                               + teammates' agents (Name/agent)
  gsh open      [--tab-id <id>] <file>     open the file in the app's viewer
  gsh <file>                               shortcut for `open` (e.g. gsh .zprofile)
  gsh read-tab  [<label|tab-id>]           read a tab's rendered output (alias: read-pane)
  gsh read-task <task-id>                  read a task's output (even w/o tab)
  gsh list-tabs       [--json]             list active tabs (alias: list-panes)
  gsh list-workspaces [--json]             list workspaces (projects)
  gsh list-tasks      [--json]             list this workspace's tasks (Task Run)
  gsh run-task <task-id> [--profile <p>] [--restart]   start a task
  gsh stop-task <task-id>                  stop a running task
  gsh restart-task <task-id>               stop + start (same profile)
  gsh send-task-key <task-id> <key>        write an interactive key (e.g. r)
  gsh new-tab [--cwd <dir>] [--title <name>] [--split h|v]
                                               open a new terminal tab (prints its id)
  gsh close-tab [<label|tab-id>]           close a tab (default: the current
                                               one) — prints the closed tab id
  gsh new-workspace <path> [--host <host>] [--name <name>] [--json]
                                               create/open a workspace (local or remote)
  gsh new-remote-workspace --host <h> --path <p> [--name <n>] [--json]
                                               create/open a remote workspace
  gsh close-workspace [<id|path>] [--json] close a top-level workspace
  gsh rename-workspace <id|path> <name> [--json]
                                               rename a workspace in the sidebar
  gsh db <list|schema|query|run|execute>   SQL databases (see `gsh db --help`)
  gsh telemetry <cmd…> | errors | show …   run observed / query the error store (see `gsh telemetry --help`)
  gsh redis [browse] --db <conn> ...       Redis command / open key table
  gsh mongo [browse] --db <conn> [--database <name>] ...
                                               MongoDB runCommand / open browser
  gsh http <list|run> <file.http>          run HTTP requests from a .http
                                               file (see `gsh http --help`)
  gsh exec [--cwd <dir>] [--timeout <s>] [--json] [--] <command...>
                                               run a shell command via the app and
                                               print its output (see `gsh exec --help`)
  gsh browse <url> [--json]                open the built-in browser tab at
                                               <url> (system browser on Linux)
  gsh orchestrate <file.ckp> [--append]    apply a .ckp pane layout: close
                      [--json]                 the workspace tabs, then open the
                                               terminals/splits + run commands
                                               (--append keeps the open tabs)
  gsh note <add|list> <dir.notebook> ...   write/list notes in a notebook
                                               folder (see `gsh note --help`)
  gsh install-skill   [--agent <a>] [--force]
                                               install the agent skills (claude,
                                               codex, pi, antigravity)
  gsh mcp --agent <app-id>                 stdio MCP server for a desktop agent
                                               app (claude-desktop, cursor,
                                               antigravity-ide, codex-desktop)
  gsh --help | --version

READ (read-tab / read-task):
  --lines N     how many lines (default 100, server cap 2000)
  --offset N    skip N lines from the anchor (pagination)
  --from-start  anchor at the start of the buffer (default: tail/end)
  Output is always chronological (top→bottom); flags only pick the window.
  read-tab without a target reads the CURRENT tab; a target may be a stable
  tab label or a tab-id.

TASKS (list-tasks / read-task / run-task / stop-task / restart-task / send-task-key):
  Task ids are stable per workspace: npm:<script> (package.json), flutter:run /
  flutter:test, json:<label> (.gsh/tasks.json). Discover them with
  `gsh list-tasks` — `[output]` marks tasks whose output `read-task` can
  read (ran this boot); ● marks tasks running right now. Task-output tabs in
  `list-tabs --json` also carry the task id as `taskId`.
  run/stop/restart/send-task-key drive the same runner as the Tasks panel, on
  local and remote workspaces alike. `list-tasks --json` lists each task's
  `profiles` and interactive `keys`.

DATABASES (db):
  Connections live per workspace in .gsh/databases.json (+ auto-detected
  SQLite files). Output is one JSON line — made for agents. Examples:
    gsh db list
    gsh db schema --db dev-local orders
    gsh db query --db dev-local --sql "SELECT * FROM orders LIMIT 5"
    gsh db run reports/daily.dbq
  Full reference: `gsh db --help`.

HTTP (http):
  Runs requests written in a .http file (REST Client / JetBrains syntax). The
  app renders the same file as a request tab. Output is one JSON line:
    gsh http list api/users.http
    gsh http run  api/users.http --request "Create user"
  Full reference: `gsh http --help`.

NOTEBOOKS (note):
  A folder named *.notebook is a notebook: one .md per note, frontmatter with
  title/tags. The app shows it as a single item and renders it as a notes tab.
    gsh note add notes.notebook --title "Túnel SSH" --tag relay --body -
    gsh note list notes.notebook
  Full reference: `gsh note --help`.

MSG:
  gsh msg --to Reviewer "diff ready in feat/x, please review"
  The target receives `[from: <your label or title> · <your harness>] <text>`
  and Enter. Sender = $GSH_TAB_ID (required). `list-tabs --json` shows each
  tab's detected `harness` (claudeCode, codex, antigravity, …) or null.
  `gsh peers` lists the agents your tab was connected to in the Agents
  graph (topbar → Visualize agents): message those with `msg --to <label|id>`.
  A desktop app on the graph (Claude Desktop, Cursor…) is messaged the same
  way; its message is queued until the app calls its `wait_messages` tool.

TEAM (office network):
  gsh msg --to "Bianca/financeiro" "I changed the payments table, check your side"
  gsh deliver --to "Bianca/financeiro" report.pdf "weekly report"
  With the team farm on (same team name and password on both GSHs), `gsh
  peers` also lists teammates' agents as `Name/agent`. The message knocks on
  their door: their agent receives it as information from a teammate (not an
  order from their user) and decides what to do; deliveries land in
  `.gsh/inbox/<your name>/` in their agent's folder. When a teammate knocks
  on yours, reply with the `gsh msg --to ...` line shown in the message.

MCP:
  gsh mcp --agent claude-desktop   (the app runs it; you normally don't)
  Desktop agent apps join the Agents graph through this server: GSH's New
  agent dialog → Desktop apps writes the `gsh` entry into the app's MCP
  config (backup kept). Tools: peers, send {to, text}, deliver {to, path,
  note?}, wait_messages
  {timeout_seconds?: 45, max 55; call again to keep waiting}, list_agents.
  Pull model: nothing is pushed to the app — messages to it are queued and
  returned by wait_messages.
  Under a GSH terminal tab it acts AS that tab (the app finds its pid in
  the tab's process tree): that is how Codex talks to other agents, since its
  sandbox blocks this shell CLI. GSH adds the entry to
  ~/.codex/config.toml at boot. wait_messages then returns the messages to the
  tab since the last call (they are also typed into the terminal).
  Finds the app via ~/.gsh/status[-debug].sock (Windows: status.json).

IDS:
  Workspace ids are opaque UUIDs — use `workspacePath` (list-tabs) / `path`
  (list-workspaces) when you need the folder on disk.

FLAGS:
  --enter         (send only) press Enter right after the text, as a separate
                  keystroke. Same as `send …` followed by `send-key … Enter`,
                  in one call.
  --focused       target the tab you are LOOKING AT, whatever it is. Resolved by
                  the app, so no id to copy. Works from outside a GSH
                  terminal too (dictation tools, scripts): with no env inherited
                  the CLI finds the app through ~/.gsh/status.sock.

TARGET:
  --tab-id <id>   target tab (--focused wins over it). Default = $GSH_TAB_ID
                  (the current tab;
                  legacy fallback $GSH_PANE_ID). Ids (t0, t1…) reset on every
                  app boot → find them with `gsh list-tabs` before targeting
                  another tab (cross-tab).

KEYS (send-key):
  Enter Tab Escape Space BSpace Up Down Left Right Home End
  PageUp PageDown Delete   |   C-<letter> (e.g. C-c = Ctrl+C)

NEW-TAB:
  --cwd <dir>     working directory (default: current directory)
  --title <name>  stable tab label (send/read-tab can target it by name)
  --split h|v     h (or right) = side by side; v (or down) = stacked.
                  Omit to open as a new tab in the same pane.
  Anchored at the emitting tab's pane/workspace. Prints the new tab id.

CLOSE-TAB:
  gsh close-tab [<label|tab-id>]
  Without a target it closes the CURRENT tab — the shell you are typing in
  ends with it. Closing the last tab of a split removes the split; closing the
  last tab of a workspace leaves an empty tab (same as the tab's "x" in the UI).

WORKSPACES (new-workspace / close-workspace / rename-workspace):
  gsh new-workspace <path> [--host <ssh-target>] [--name <title>] [--json]
  gsh new-remote-workspace --host <ssh-target> --path <remote-path> [--name <title>] [--json]
  Alias: `gsh open-workspace`. Adds a top-level workspace in GSH's
  sidebar (local or remote), selects it, and ensures an initial terminal tab is
  opened. For remote workspaces, --host specifies the SSH host or ~/.ssh/config
  alias (automatically registered if not already present).
  Idempotent: if already open, selects it and returns its info. Prints the
  workspace id (or JSON object with --json).

  gsh close-workspace [<id|path>] [--json]
  Closes a top-level workspace (ends its tabs; files on disk are kept). Target
  may be a UUID, directory path, or unique name (default: current workspace).
  Prints the closed workspace id.

  gsh rename-workspace [<id|path>] <new-name> [--json]
  Updates the display title of a workspace in the sidebar. Target may be a UUID,
  directory path, or unique name (default: current workspace).

EXAMPLES:
  gsh send "echo hi" && gsh send-key Enter
  id=$(gsh new-tab --cwd ~/proj --title Worker --split h)
  gsh send --tab-id "$id" --enter "npm test"   # text + Enter in one call
  gsh close-tab "$id"                      # close it when done (or: Worker)
  ws=$(gsh new-workspace ~/proj/my-service --name "My Service")
  gsh rename-workspace "$ws" "Renamed Service"
  gsh close-workspace "$ws"
  rws=$(gsh new-remote-workspace --host workspace-vm --path /home/ubuntu/wt --name "Task 1")
  gsh send-key C-c
  gsh send --tab-id t3 --enter "ls"
  gsh .zprofile          # opens the file in the viewer (relative to tab cwd)
  gsh open ~/.gitconfig
  gsh read-tab Extension --lines 50        # last 50 lines of tab "Extension"
  gsh read-tab t4 --lines 200 --from-start
  gsh list-tasks                           # discover task ids (npm:dev, ...)
  gsh read-task npm:dev --lines 80         # tail of task "npm:dev" output
